# 设计方案：词语对照表自动学习（直出模式）

> 状态：**已实现（v1.6.0）**。核心模块 `voxscribe/glossary.py`（1500 行、42 个单测）、本地替换与 prompt 合并已接入 pipeline、首页直出模式编辑自动触发学习、设置页「管理词语表…」确认/启停/删除；JSONL 试验日志写入 `data/logs/glossary_learn.jsonl`。
>
> 目标：用户在「直出」模式下修改/删除转写结果中的词语后，系统自动提取「错误词 → 正确词」对照关系，经确认/合并后写入词语表，后续自动纠正同类错误。

## 一、现状与问题

- 词语表目前是 [config.py](D:/Project/voice2text/voxscribe/config.py#L103) 里的 `glossary` 纯文本，设置页 [dialogs.py](D:/Project/voice2text/voxscribe/gui/dialogs.py#L342) 手动维护，格式「正确写法：常见误写」。
- 它只作为 user prompt 的「术语表」块传给 DeepSeek（[prompts.py](D:/Project/voice2text/voxscribe/prompts.py) 的 `GLOSSARY_MARKER`），**没有本地替换、没有结构化存储、不会从用户修改中学习**。
- 因此用户每次遇到同一个错词都要手动加一次，且模型是否遵守术语表仍有随机性。

## 二、设计原则

1. **只在直出模式学习**：直出模式下用户的修改才是"对转写的纠错"；对人/对AI 模式的大量改写不能当术语（会误学）。
2. **基线清晰**：比较基准是直出模式**最终显示的整理稿**（不是 ASR 原文），避免把 DeepSeek 自己的润色当成用户纠错。
3. **本地优先**：抽取、存储、应用都在本机完成；只有用户确认的术语才会（可选地）写进发给 DeepSeek 的 prompt。
4. **宁缺毋滥**：只学短小的词语替换；大段重写、标点调整、繁简转换、纯删除一律默认忽略或强确认。
5. **可撤销**：误学随时可删，最近一次学习支持一键撤销。

## 三、比较规则（核心算法）

输入：`before`（直出模式最终稿基线）、`after`（用户编辑后的文本）。

### 3.1 预处理

- Unicode NFKC 归一化；统一全角/半角标点；去掉首尾空白。
- 记录基线文本长度；若 `after` 为空或等于 `before` → 结束。
- 快速排除：`after` 与 `before` 的编辑距离 > 基线长度的 30%，或修改字符数 > 40 → 视为整段重写，不学习。

### 3.2 字符级对齐 + 词边界扩张

用 `difflib.SequenceMatcher(None, before, after, autojunk=False)` 得到 `get_opcodes()`：

- 只处理 `replace`、`delete` 两种 opcode（`insert` 不是"错词纠正"场景，忽略）。
- 对每个变更片段：
  1. 先裁掉首尾相同的字符（避免 `SequenceMatcher` 把公共字包进片段）；
  2. 用标点/空白分割，把片段收缩到不含标点、空格的词边界；
  3. 片段长度限制：`old`/`new` 均 ≤ 12 个字符（中文词通常 2~6 字；英文按空白词取整）；
  4. `replace` 时 `old != new`，且二者不能仅为繁简差异、大小写差异、空白差异；
  5. `delete` 时 `old` 长度 ≥ 2 才进入候选（删除单字噪声太大），且要求删除位置前后文本能自然衔接（不破坏句子结构）。

### 3.3 过滤（防误判）

以下情况默认不学习（或进入"强确认"）：

- 片段含句号/问号/换行/引号等标点，或跨越句子边界；
- 片段含纯数字、URL、邮箱、手机号、日期（疑似敏感信息）；
- `old` 或 `new` 是常见停用词/语气词（的、了、吗、吧、这个、那个、然后、就是……）；
- 单字替换（如「的→得」）默认不学；除非同一对在 3 次不同会话中重复出现；
- 总变更片段数 > 5，或总变更字符 > 25 → 视为大改，只提示不自动学；
- 片段在 `after` 中出现次数 > 1（用户只改了一处，别处没改，可能是局部润色而非术语）。
- 简繁/全半角差异：交给字形归一化（见前一份简繁方案），不进入词语表。

### 3.4 候选数据结构

```text
Candidate {
  wrong: str        # 原文错词（如「阴轨」）
  correct: str      # 用户改成（如「音轨」）；delete 时为空
  kind: "replace" | "delete"
  context: str      # 前后各 8 字，仅用于确认对话框展示，不落盘
  confidence: float # 0~1，由规则+历史频次计算
}
```

置信度示例：`replace` 双字以上 0.75；单字 0.4；`delete` 0.5；历史已出现 2 次 +0.2；用户手动确认 +0.3。

## 四、触发时机

| 时机 | 行为 |
| --- | --- |
| 用户停止编辑 1.2 秒（debounce） | 比较并生成候选（不弹窗，只更新待确认状态） |
| 结果框失焦（点击别处） | 同上 |
| 点击「复制文字」 | 若用户已修改，先学习再复制；复制成功后提示"已学到 N 条" |
| 开始下一次录音 / 切换模式 / 关闭窗口 | 冲刷待处理的编辑 |
| 转换完成、结果文本被替换 | 重置基线，不学习应用自身的替换 |

前置条件（全部满足才学习）：

- `quick_mode == "direct"`；
- `quick_state == "idle"` 且不是占位提示文本；
- 有基线文本，且基线未被"应用自身"更新（区分用户编辑与程序替换）；
- `auto_glossary_learn` 开关为开。

## 五、误判处理与确认机制

### 5.1 分级处理

| 置信度 | 处理 |
| --- | --- |
| ≥ 0.85（重复出现/用户确认过） | 自动写入词语表，显示 5 秒可撤销提示 |
| 0.6 ~ 0.85 | 写入"待确认"，不自动应用；结果区下方出现轻量提示：「学到 1 条：阴轨 → 音轨 [采纳] [忽略]」 |
| < 0.6（单字、删除、含敏感信息） | 只在设置页「词语学习 → 待确认」列出，不主动打断 |

### 5.2 确认 UI

- 首页结果区下方（复用 `home_inline_hint` 的位置）：一行非阻塞提示，带 [采纳] [忽略] [撤销]。
- 设置页新增「词语学习」卡片：
  - 开关：启用自动学习（默认开）；
  - 列表：词语 / 类型 / 次数 / 来源（学习/手动）/ 状态（启用/停用）；
  - 分区：已生效、待确认、冲突；
  - 按钮：全部采纳、清空学习记录、重新学习。
- 默认策略：**首次出现只提示不自动应用；同一错误出现 2 次或用户点「采纳」后自动应用**。既满足自动化，又避免第一条误学污染。

## 六、存储格式

新增 `data/glossary.json`（本地、原子写入，保留 `.bak`）：

```json
{
  "version": 1,
  "updated_at": "2026-10-23T00:00:00+08:00",
  "entries": [
    {
      "wrong": "阴轨",
      "correct": "音轨",
      "kind": "replace",
      "source": "learned",
      "enabled": true,
      "confidence": 0.9,
      "count": 2,
      "created_at": "2026-10-22T21:00:00+08:00",
      "updated_at": "2026-10-23T00:00:00+08:00"
    },
    {
      "wrong": "那个",
      "correct": "",
      "kind": "delete",
      "source": "learned",
      "enabled": false,
      "confidence": 0.4,
      "count": 1
    }
  ]
}
```

- `settings.glossary` 手动文本继续保留，作为「手动条目」，优先级最高；首次启动时可解析成结构化条目。
- 手动格式约定不变：「正确写法：常见误写」，兼容现有用户。
- 学习条目与手动条目合并时，手动条目覆盖同 wrong 的学习条目。
- 待确认候选可以放 `pending` 数组或内存（推荐内存 + 可选落盘，避免半成品长期堆积；落盘方便崩溃恢复，可加 `pending` 字段）。

## 七、冲突合并策略

| 场景 | 规则 |
| --- | --- |
| 相同 `wrong` + 相同 `correct` | 累加 `count`，提升 `confidence`，更新 `updated_at`，不新增 |
| 相同 `wrong` + 不同 `correct` | 手动条目优先；都是学习条目则保留 `count` 更高者，另一条标记 `conflict` 待用户选择；绝不静默来回覆盖 |
| 删除规则 vs 替换规则 | 同 `wrong` 时替换优先（更具体）；删除规则需要用户确认 |
| 映射成链（A→B、B→C） | 应用时做一次传递闭包；检测到环（A→B、B→A）立即停用环上条目并提示 |
| 条目数量上限 | 默认 200 条；超出时按「未使用时间 + 置信度」淘汰最低的，待确认条目不计入 |
| 用户手动编辑词语表 | 保存时重新解析，手动条目胜出；被覆盖的学习条目保留但停用，不直接删除，避免用户误删 |

## 八、隐私处理

- 抽取和存储完全本地完成，**不上传**原文、修改后文本或上下文；不写日志正文，只记录条数/耗时等统计。
- 存储内容只有词对（wrong/correct）和计数，不存整句、不存音频、不存原始录音。
- 敏感模式跳过：含数字、邮箱、URL、手机号、身份证号样式的片段默认不学（或仅入待确认）。
- 只有 `enabled=true` 的替换条目才会：
  1. 作为本地替换规则应用；
  2. 可选地拼进发给 DeepSeek 的术语表 prompt（设置页提供「同时发送给 AI」开关，默认开；关闭则只本地替换，保证隐私）。
- 提供「清空学习记录」按钮；`data/glossary.json` 位于用户本地数据目录，随软件卸载可一并删除。

## 九、应用流程（实现视角）

### 9.1 模块

新增 `voxscribe/glossary.py`：

```text
parse_manual_glossary(text) -> list[Entry]
load_store() / save_store(entries)      # data/glossary.json，原子写
extract_candidates(before, after) -> list[Candidate]
merge_candidates(entries, candidates) -> (entries, pending, conflicts)
apply_replacements(text, entries) -> str   # 本地替换/删除
build_prompt_glossary(entries) -> str      # 只含 enabled replace 条目
```

新增测试：`tests/test_glossary.py`（纯函数，不需要 GUI/网络）。

### 9.2 管线集成

1. ASR 完成 → `apply_replacements(transcript.text)`（只对中文启用；术语表在 DeepSeek 之前生效）；
2. 拼 `RefineOptions.glossary` 时用 `build_prompt_glossary(manual + learned)`；
3. DeepSeek 返回 → 再执行一次 `apply_replacements(refined.text)`（防止模型把词改回去）；
4. 文件页导出同样走第 3 步后的文本。

### 9.3 界面集成

- `_on_quick_done`：记录 `self._learn_baseline = final_text`（以及模式、是否直出）；
- 绑定 `home_text` 的 `<<Modified>>`/`<FocusOut>` + `after(1200)` debounce；
- 用户编辑 → `extract_candidates` → 分级：
  - 自动采纳：写 store，状态栏提示 + 撤销按钮；
  - 待确认：`home_inline_hint` 显示一行操作；
- 用户点「复制文字」/开始新录音/切模式/关窗时冲刷；
- 程序替换文本（转换完成、清空）时更新基线，不触发学习。

### 9.4 实施顺序

1. 先做纯函数 `extract_candidates` + 单测（覆盖替换/删除/标点/繁简/大改/敏感信息）。
2. 再做 `glossary.py` 存储与合并 + 单测。
3. 接入管线本地替换与 prompt 术语表，补集成测试。
4. 最后做首页学习提示与设置页「词语学习」管理界面。
5. 默认开启「同一错误第 2 次自动生效」，首条只提示；提供关闭开关。

## 十、开放问题（需产品决策）

1. 删除类规则是否默认启用？建议默认只入待确认，不自动应用（误删风险高于替换）。
2. 是否允许学习英文/中英混合词对？建议允许，但按空白分词，且不学纯大小写差异。
3. 是否把学习条目发送给 DeepSeek？建议默认发送（效果更好），并给隐私开关；本地替换始终生效。
4. 词语表容量与清理策略：默认 200 条 + 手动置顶，避免无限增长。
